# 冲压车间垫板货架层位绑定管理系统

## 项目简介

独立五金冲压车间垫板与库房货架分层绑定管理系统，维护垫板档案、货架层位、一对一绑定关系和调整记录，并提供垫板领用归还闭环管理（领用离架、归还上架、逾期与占用监控）。

## 技术栈

- 前端：Vue 3、Vite 5、Element Plus、Pinia、Axios
- 后端：Spring Boot 3、JDK 17、MyBatis-Plus、Maven
- 数据：MySQL 8、Redis 7
- 部署：Docker Compose、Nginx

## 垫板领用归还闭环

- 领用：从垫板档案中选择在架垫板，登记领用人、产线/工位、用途、领用时间与预计归还时间；领用成功后垫板自动从原层位离架（`shelf_layer_code`/`bind_time` 置空），层位占用数同步减少，并写入 `CHECKOUT` 调整记录。
- 归还：必须选择当前未被占用（空闲）的层位并记录归还时间；归还后自动恢复垫板与层位的绑定（含绑定时间），并写入 `RETURN` 调整记录。
- 闭环约束：同一块垫板存在未归还记录时禁止重复领用；已归还记录禁止重复归还；禁止归还到已占用层位；领用中的垫板禁止层位绑定/解绑/编辑/删除。
- 台账：`/borrow` 页面支持按状态（领用中/已逾期/已归还）、垫板编号、领用人、领用日期区间筛选，展示逾期标记与当前占用（领用人、产线/工位），顶部统计卡片支持点击快速筛选。
- 逾期判定：逾期是“领用中且预计归还时间已过”的**实时派生状态**，不单独落库——台账列表、`OVERDUE` 筛选、概览/台账的“逾期未还”统计与档案页逾期标记均在查询时按 `expected_return_time < NOW()` 计算，预计归还时间一过，刷新页面（数据概览、领用台账、垫板档案）即同步标红，无需任何定时任务或手工状态流转；归还后逾期计数立即清零。
- 时间格式：前后端时间统一按 `yyyy-MM-dd HH:mm:ss` 交互（后端 `JacksonConfig` 为 JSR-310 `LocalDateTime` 配置序列化/反序列化器；GET 查询参数由 `spring.mvc.format.date-time` 绑定）。注意 `spring.jackson.date-format` 只对旧版 `java.util.Date` 生效，对 `LocalDateTime` 无效，不能替代该配置。

## 垫板保养台账

- 登记：管理员在 `/maintenance` 页面为垫板登记保养类型、处理人、保养时间、保养结果（正常/已修复/异常待处理/报废建议）和备注，并将垫板标记为**可用（AVAILABLE）/待检（PENDING）/停用（DISABLED）**。
- 自动离架：在架垫板被标记为**待检/停用**时自动从层位离架（`shelf_layer_code`/`bind_time` 置空），并写入 `UNBIND` 调整记录；离架后不再计入层位占用与配额校验，已满层立即释放可给其他垫板归还上架，下调配额也不再被卡住。恢复为可用时不自动回架，需重新绑定层位或走归还上架流程。
- 闭环约束：待检、停用垫板不可被领用（领用弹窗禁用并提示原因），归还时也不能作为归还目标（领用台账“归还”按钮禁用，后端二次校验）；待检/停用垫板同样不可绑定/换绑层位或编辑换层（前端禁用，后端二次校验），恢复为可用后领用/归还/上架闭环正常。
- 筛选：支持按垫板当前状态、垫板编号、保养日期区间筛选，顶部可用/待检/停用统计卡片支持点击快速筛选。
- 详情：展示垫板档案、最近一次保养、完整状态变更时间线与全部保养记录。
- 一致性：状态落库在 `pad_info.maintenance_status`，层位占用始终由 `pad_info.shelf_layer_code` 实时统计，刷新后数据概览、层位卡片、归还可选层与档案绑定四处保持一致，不留无主占用；档案页支持按保养状态筛选并提供“保养”快捷入口。

## 垫板报废出库

- 前置流程：保养登记给出“报废建议”（保养结果 `SCRAPPED`）后，库房在 `/scrap` 页面**单独办理报废出库**，登记批准人、报废去向、出库时间并**至少上传一张报废照片**（多张，自动压缩）。
- 出库效果：垫板档案状态置为**已报废（SCRAPPED）**；若仍在架则自动离架（`shelf_layer_code`/`bind_time` 置空）并写入 `SCRAP` 调整记录，层位占用立即释放；待检/停用等本已离架的垫板不重复写层位记录。
- 终态冻结：已报废垫板不能再被领用、归还回架、绑定/换绑/解绑、编辑、删除，也不能再登记保养；报废出库不可重复办理（一垫板一记录，后端唯一约束 + 状态双重校验）。领用中的垫板须先归还，无“报废建议”的垫板不能办理出库。
- 台账回看：`/scrap` 页面支持按垫板编号、去向、批准人、出库日期区间筛选，展示出库前层位与照片缩略图，详情可查看全部照片；统计卡片展示累计报废、待出库（有报废建议未出库）与本月报废数量。
- 入口：保养台账“报废建议”记录、档案页有报废建议的垫板均可一键跳转报废出库；档案页已报废行展示“已报废出库/档案冻结”并提供报废记录入口。
- 一致性：状态落库在 `pad_info.maintenance_status=SCRAPPED`，层位占用始终由 `pad_info.shelf_layer_code` 实时统计，刷新后数据概览在架数、层位占用、领用/归还可选范围与档案状态保持一致。

## 货架层位容量配额

- 配额维护：每层在 `shelf_layer.capacity` 维护容量配额（新建分层默认 10），层位编辑弹窗可调整；**下调配额不得低于当前在架数**，后端二次校验。
- 上架约束：层位绑定、换绑（重分配）、新建档案带层位、归还上架、批量导入均不得让该层超过配额；校验在事务内对层位行加锁（`SELECT ... FOR UPDATE`），防止并发超配额。
- 归还目标：已满层位（占用数 ≥ 配额，含配额为 0 的层位）不能作为归还目标，归还弹窗禁用并标注，后端二次校验。
- 展示：层位页卡片与数据概览按 `在架数/配额` 展示占用进度（空闲/有余量/将满/已满），档案绑定与归还层位下拉同步显示占用并禁用已满层位。
- 一致性：层位占用数始终由 `pad_info.shelf_layer_code` 实时统计，刷新后档案绑定、层位占用与调整记录保持一致。

## 层位封锁管理

- 登记封锁：库房发现层位**破损、待清扫或正在检修**时，在 `/layer-block` 页面单独登记封锁，必填封锁类型、**封锁原因、开始时间与经办人**；同一层位同一时间仅允许一条“封锁中”记录（事务内行锁层位校验，防止重复登记与并发占位交错）。
- 封锁约束：封锁期间该层**禁止绑定、换绑（重分配）、归还上架与导入占位**；校验统一收敛在上架入口 `lockAndAssertCapacity`（事务内行锁 + 封锁检查），批量导入预览/确认同步拦截并提示。封锁不强制已在架垫板离架：在架垫板仍可领用离架、解绑移出，层位删除须先解除封锁。
- 解除封锁：必须填写**解除结论**（可登记解除时间与解除经办人，缺省取登记经办人），解除时间不能早于封锁开始时间；已解除记录禁止重复解除（条件更新防并发）。解除后层位自动恢复可上架。
- 台账回看：列表支持按**封锁状态（封锁中/已解除）、层位编码、封锁类型与封锁日期区间**筛选，顶部统计卡片（封锁中/已解除/本月封锁）支持点击快速筛选。
- 一致性：层位列表/单查接口实时带出当前生效封锁记录，刷新后**层位可选范围**（绑定/换绑/建档/归还下拉禁用并标注“封锁中”）、**占用进度**（层位卡片与数据概览展示封锁标识）与**档案绑定**保持一致；层位管理卡片提供“登记封锁/解除封锁”快捷入口。

## 层位临时扩容

- 登记扩容：旺季到货时库房在 `/layer-expand` 页面把某层配额临时加大，必填**扩容原因、新配额、生效时段（开始/结束时间）与经办人**；新配额必须大于原配额（登记时快照留存 `original_capacity`），同一层位同一时间仅允许一条“待生效/生效中”记录（事务内行锁层位校验）。
- 扩容约束：扩容期内（生效时段内）层位**绑定、换绑、新建档案带层位、归还上架与批量导入统一按新配额校验**，校验仍收敛在上架入口 `lockAndAssertCapacity`（与登记扩容同一把层位行锁，并发口径一致）；开始时间未到的“待生效”记录不参与校验。
- 到期与提前结束：**到期自动回到原配额**（容量校验按生效时段实时判断，台账刷新时状态落为“已到期”并由系统补写结束信息）；未到期也可**提前结束**，必须填写**结束结论**（可登记结束时间与结束经办人，缺省取登记经办人），结束后立即按原配额校验。回到原配额后已在架垫板保留不强制离架，但占用未降到原配额以下前不可再上架。
- 台账回看：列表支持按**生效状态（待生效/生效中/已到期/已结束）、层位编码与生效日期区间**筛选，顶部统计卡片（生效中/待生效/已到期/已结束）支持点击快速筛选。
- 一致性：层位列表/单查接口实时带出当前生效扩容记录与实际配额（`activeExpand`/`effectiveCapacity`），刷新后**层位占用进度**（层位卡片与数据概览按新配额计算百分比并标注“扩容中”）、**可选范围**（绑定/换绑/建档/归还下拉按新配额放行并标注）与**档案绑定**保持一致；层位管理卡片提供“临时扩容/结束扩容”快捷入口，扩容中的层位须先结束扩容或待其到期后才能删除。

## 换模垫板预留
- 登记预留：换模前库房在 `/pad-reserve` 页面把指定**在架垫板**预留给即将上线的模具，必填**模具编码、预留板清单、生效时段（开始/结束时间）与经办人**（可登记模具名称、上线产线/工位）；待检/停用/已报废、未在架或领用离架的垫板不可预留，同一垫板在时段重叠的未释放预留中不可重复登记（逐块行锁垫板，防止与领用/解绑并发交错）。
- 预留约束：预留登记后至到期前（含**待生效**时段，避免生效前被领走）这些板**不能被其他产线领用，也不能解绑/换层**（含档案编辑换层、保养强制离架、报废出库，后端二次校验）；预留不强制层位状态，垫板仍在原位计入层位占用，归还上架不受影响。
- 到期与手工释放：**到期自动释放**（台账刷新时状态落为“已到期”并由系统补写释放信息，约束按结束时间实时判断，不依赖状态列刷新）；未到期也可**手工释放**，必须填写**释放结论**（可登记释放时间与释放经办人，缺省取登记经办人），条件更新防并发重复释放。**待生效**预留尚未到开始时间，可立即释放（释放时间允许早于预留开始时间）；已到点开始生效的预留仍要求释放时间不早于开始时间。释放后垫板立即恢复可领。
- 台账回看：`/pad-reserve` 列表支持按**预留状态（待生效/生效中/已到期/已释放）、模具编码/名称、垫板编号、经办人与预留日期区间**筛选，顶部统计卡片支持点击快速筛选，展开行可查看预留板清单（含登记时层位快照与垫板当前层位/状态对照）。
- 一致性：预留约束落库在 `pad_mold_reserve_record`/`pad_mold_reserve_item`，垫板档案分页接口实时带出 `reserveId/reserveMoldCode`；刷新后**领用可选板**（领用下拉禁用并标注预留模具）、**层位占用**（预留板仍在架，占用数不变）与**档案状态**（档案页“已预留”标识、领用/重分配/解绑禁用）保持一致；档案页在架可用垫板提供“预留”快捷入口，已预留板提供“预留记录”入口。

## 到货待检（待检层）

- 登记到货：新到垫板在 `/arrival` 页面先落**待检层**，必填**经办人**与**批内垫板清单**（逐块登记编号，可选模具/尺寸），可登记到货时间（默认当前）、供应商与备注；系统生成到货批次号（`DH` 开头），批内每块垫板自动建档（`stock_status=QUARANTINE`、无层位）。
- 待检约束：待检层垫板**不能领用、换绑（绑定/解绑/编辑换层）或计入可用库存**，也不能登记保养、报废出库、换模预留或删除档案（前端禁用并标注，后端在领用/绑定/保养/报废/预留/删除入口二次校验）；仅可编辑编号、规格等非层位信息。
- 质检判定：**质检通过**整批转正式层——逐块指定目标层位（可一键统一层位），层位须存在、未封锁且不超实际配额（事务内行锁层位逐块校验，同层多块不会超配额），上架后 `stock_status=OFFICIAL` 并写入 `BIND` 调整记录，垫板恢复可领用；**判退**则整批离库——批内垫板 `stock_status=REJECTED`，档案冻结留存，不再参与任何库存操作。通过/判退均必填**质检结论**（可登记质检时间与质检人，缺省取经办人），已判定批次禁止重复判定（事务内行锁批次 + 条件更新防并发）。
- 台账回看：`/arrival` 列表支持按**批次状态（待检中/质检通过/判退离库）、批次号、垫板编号、经办人与到货日期区间**筛选，顶部统计卡片（待检中批次/待检占用块数/质检通过/判退离库/本月到货）支持点击快速筛选，展开行可查看批内垫板清单（含转正式层位与垫板当前状态对照）。
- 一致性：库存状态落库在 `pad_info.stock_status`，待检占用按 `QUARANTINE` 实时统计；刷新后**数据概览**（“到货待检占用”卡片单独标出待检块数与待检批次数）、**档案页**（“到货待检/已判退离库”标识与操作冻结）、**领用/保养/报废/预留下拉**（禁用并标注）与**到货台账**保持一致；档案页待检/判退行提供“到货记录”快捷入口。

## 交班盘点

- 开单清点：交班时库房在 `/inventory` 页面按**层位或整货架**开单清点在架垫板，必填**班次（白班/中班/夜班）与盘点人**；开单时快照覆盖层位的在架垫板为账目明细，同一层位同一时间仅允许一张“盘点中”单据（事务内行锁覆盖层位，防止并发开单交错）。
- 逐块标记与补录：账目明细逐块标记**账实相符/缺失**，现场多出的垫板按所在层位**补录多出**（层位须在覆盖范围内、编号不可与账目清单或已补录重复，能匹配档案时自动回填垫板信息）；全部账目明细标记完毕才能提交。
- 差异闭环：提交时存在差异（缺失/多出）必须登记**差异原因**，单据进入**待闭环（未平账）**；账实相符的单据提交即自动闭环（系统补写闭环信息）。差异处理完毕后**闭环**，必填**闭环结论**（可登记闭环时间与闭环人，缺省取盘点人），闭环时间不能早于提交时间，条件更新防并发重复闭环；盘点中单据可取消，取消后可重新开单。
- 未平账约束：待闭环单据覆盖的层位**禁止归还上架**（归还弹窗禁用并标注，后端 `assertNotUnbalancedForReturn` 二次校验），闭环后自动恢复；绑定/换绑/建档/导入不受盘点影响。
- 台账回看：列表支持按**状态（盘点中/待闭环/已闭环/已取消）、班次、覆盖层位、单号与开单日期区间**筛选，顶部统计卡片（盘点中/待闭环/已闭环/本月盘点）支持点击快速筛选；详情展示覆盖层位实时占用与逐块明细（含垫板实时层位对照，开单后移层即时提示）。
- 一致性：未平账状态落库在 `pad_inventory_sheet.status=SUBMITTED`，层位列表/单查接口实时带出覆盖本层的待闭环单据（`activeUnbalanced`），刷新后**数据概览**（层位“未平账”标记）、**层位页**（差异原因横幅与标记）、**归还弹窗**（禁用层位并展示未平账原因）与**盘点页**（待闭环单据与差异原因）四处保持一致；层位管理卡片提供“发起盘点/盘点闭环”快捷入口。

## 常见问题

- 依赖下载失败：检查 Maven、npm、Docker 镜像源和网络。
- 端口占用：修改 `.env` 中 `FRONTEND_PORT`、`BACKEND_PORT`、`MYSQL_PORT`、`REDIS_PORT`。
- 页面接口失败：先确认 `npm run build` 已通过，再检查 Docker 中 backend 是否启动、Nginx `/api` 代理是否可达。
